# Scope of Source comparisons

Source means a supplied incident report or other failure description. A Target
is the code being checked. The owner requirement states what that code must
preserve; an incident report is not that requirement's authority.

## Implemented paths

| Path | Current method | What it can establish |
| --- | --- | --- |
| Report to condition | Bounded lexical projection of quoted operation/error/order spans | A reproducible candidate tied to supplied text |
| Condition to caller | Static syntax matching, documented caller preparation, finite supported families | Applicability within the declared binding rules |
| Candidate repair | Deterministic family rewrite or an explicitly supplied candidate | A candidate for later checks, not an accepted repair |
| Source/No Source comparison | Equal budgets, a named baseline, common caller/requirements and confirmation envelope | A difference between those finite planners |
| Optional IR/JEV workflow | Separately recorded proposals and applicability review | Review artifacts; never execution authority |

The grammar includes lifecycle phase and occurrence, and the cleanup path can
select reported error or deletion-order conditions. It is a predefined primitive
library, not unrestricted synthesis of failure mechanisms. See
[`reliability_source_conditions`](../reqlox_core/reliability_source_conditions.py),
[`reliability_incident_conditions`](../reqlox_core/reliability_incident_conditions.py)
and [`candidate`](../reqlox_core/reliability_reuse.py).

## Baselines matter

`FIXED_GENERIC_V1` uses a fixed list of generic cleanup conditions.
`TARGET_GUIDED_SOURCE_BLIND_V1` can also prioritize conditions from Target
deletion syntax without reading the Source payload. Record the selected policy,
full available pool, selected conditions and budget for each arm. A condition
outside one baseline is not necessarily outside the shared primitive library.

If both arms exhaust the same condition set, equal final discovery counts cannot
identify an ordering benefit. An ordering study needs a predefined measure such
as calls to the first counterexample, an equal finite budget, and a competitive
source-blind planner. Increasing the search space alone does not establish
natural Source value. A Source-exclusive hard-coded condition can merely weaken
the control; a useful control gets comparable primitives and Target information.

Freeze discovery inputs and selection rules before outcomes. Use the same
requirements, repair policy and confirmation checks in both arms. Keep normal
baseline failures, unreached faults and missing results in the denominator.
Avoid revising the baseline after inspecting an outcome and presenting it as
the original experiment.

## Claims to keep separate

The existing copied api/worker records establish bounded detection and repair
checks for known code. They are not an independent Source comparison. A past
model call is not the repair generator used by every run. Saved-response replay
does not query a provider. An audit checks retained records without rerunning a
Target; hashes establish content identity, not independent authenticity.

Unknown-OSS generalization, natural incident transfer, Source added value,
probability calibration and human-effort savings need separately designed
evidence. The archived copied-Target ledger remains at 15/15 campaigns and 62/120
charged seconds. Separate test launches cannot renew that authorization or be
counted as new qualification. See [Testing](testing.md) for the offline boundary.
