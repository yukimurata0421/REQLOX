# Historical and operational records

Use [the project overview](../../README.md), [reviewer guide](../reviewer-guide.md)
and [current delivery](../current-delivery.md) for a first review. This index keeps
dated release, validation and administrative records accessible without making
them the introductory reading path.

| Record | Scope |
| --- | --- |
| [Previous README](../../README.history-20261015.md) | Overview before the reviewer-facing reorganization |
| [Latest delivery](../current-delivery.md) and [checkpoint](../../publication/read-only-delivery-20261015.json) | Observed application commit/runtime, not a later documentation revision |
| [Hosted history](../hosted-deployment.md) | Earlier deployments and their observation windows |

| [CI checkpoint](../../publication/ci-delivery-20261015.json) | Earlier tested commit and test count |
| [Coverage snapshot](../../publication/coverage-validation.json) | Historical runtime denominator and per-file gates |

| [Historical provider usage](../historical-vertex-ai-usage.md) | Safe summary of a retained earlier call, with raw files private |

Different test counts or repository visibility at different times are not
interchangeable measurements. Check each record's timestamp, revision, method
and denominator. Existing JSON, old failures and unknown outcomes remain intact.
The current README reorganizes navigation; it does not rewrite those records.
Video production assets are kept in the development checkout.
