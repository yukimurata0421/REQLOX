# Public Scope and Remaining Work

This page separates the usable public package from the broader project
direction. Its filename is retained for existing links.

## Available in the public package

| Area | Current scope |
| --- | --- |
| Installation | A Python package with CLI entry points and bundled local UI assets. |
| Target inspection | Bounded static inventory and supported API/context bindings. |
| Condition preparation | Supplied quoted conditions and bounded lexical Source projection. |
| Repository experiments | Finite contracts for atomic file writes, atomic contexts, async resources, and elapsed-time TTL behavior. |
| Repair | Candidate generation and confirmation in snapshots; checkout files remain unchanged. |
| Comparison | Source and No Source records, including separate paired loops. |
| Evaluation preparation | Documented path callers and supplied pure-Python dependency capsules; unsupported prerequisites are held. |
| Probability review | Missing-label coverage, diagnostic scores, a frozen calibration candidate, and confirmation-input checks. |
| Verification | Saved inputs, archived methods, hashes, result checks, and current claim limits. |
| Demo | Two known controls for lock cleanup, local evidence display, and reduced result download. |
| Optional models | An explicitly configured cloud adapter with a persistent call/reservation ledger. |
| Local knowledge | Explicit public-page retrieval, supplied-text import, hybrid search, native IR closure and atomicity, bounded parallel review, and partial scores. |
| SQL reference | Packaged PostgreSQL and pgvector DDL; no runtime DB connection or deployment. |

The paired requirement preparation path currently supports `atomic_file` and
`atomic_context`. General inventory also recognizes `async_resource` and
`elapsed_ttl` shapes. A family name does not imply support for every API or
implementation of that family.

## Outside this public slice

The package does not include bulk incident acquisition, the development corpus,
private provider responses, general target discovery, a complete semantic
incident-verification service, or production repair. It does not reproduce the
full development workspace.

The current reusable document and IR methods are described in
[Local incident knowledge](local-knowledge.md). Their owned controls and mock
provider checks do not turn the broader semantic workflow into a qualified
incident-to-Target service.

Included schemas and measurement helpers expose useful interfaces; they do not
make every broader workflow stage available as a public command.

## Verification still required

The [current UI validation](../publication/ui-validation.json)
reports the checked public interfaces and bounded owned controls. The earlier
evaluation and runtime records cover prior package snapshots. These checks do not establish
live model connectivity, arbitrary target compatibility, or production repair.

Independent unused-target qualification, natural Source contribution,
probability calibration, human-effort reduction, and total-cost savings are
not established by those implementation checks.

## Future delivery work

Public cloud hosting requires its own authentication, request and cost bounds,
worker-isolation arrangement, data handling, and deployment verification.
The current loopback server is not that deployment. No cloud deployment is
included in the recorded public validation.

Additional targets and incident workflows can extend this slice after their
interfaces and evidence boundaries are specified and checked. This page does
not promise a delivery schedule or imply authorization to expand execution.

Use the [documentation index](README.md) for current interfaces and
[Evaluation](evaluation-plan.md) for measurement scope.
